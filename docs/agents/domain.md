# Domain docs

采用单一上下文布局：

- 根目录 GLOSSARY.md：领域术语。
- docs/adr/：架构决策。

## 阅读规则

探索代码前，读取 GLOSSARY.md 和与当前工作有关的 ADR。
文档不存在时正常继续，由 domain-modeling 在概念或决策明确后按需创建。

## 文档边界

- 当前实现由源码、测试和配置表达；README 只保留简介、运行入口、必要权限和限制。
- ADR 记录重要决策的背景、取舍和后果；计划中的决定明确标注，实施进度留在 Issue。
- 待办和验收结论保存在 GitHub Issues；完成后停止维护对应规格的本地副本。
- 截图、日志和测量结果输出到忽略的 `test-results/`，由相关 Issue 标明证据位置及适用版本。
- 清理旧规格前，承接其中仍有效的架构理由和未完成事项；仓库内不另建历史规格归档。

## 使用规则

- 使用术语表中的标准名称及定义。
- 术语存在歧义时明确指出，不擅自改变含义。
- 与既有 ADR 冲突时，明确说明冲突与重新讨论的理由。
- 术语表只记录领域概念；实现取舍记录到适当的决策文档。
