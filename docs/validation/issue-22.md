# Issue #22 — 宠物本体上下文菜单

基线为 `c5a8b1f`，包含已交付的 #4 拖动、#6 隐藏与 #15 自由活动。菜单仅含 Hide Mosey 与 Quit Mosey；诊断入口仍在菜单栏。没有占位设置项。

## 实现边界

渲染器把右键／Control-click 的 contextmenu 发送为既有受限 input 通道上的严格类型事件；普通左键处理排除 Control。主进程重复校验发送者、可见性、当前可见像素命中及动作身份。拖动捕获期间忽略辅助点按。菜单使用 Electron 原生 Menu，在经过命中校验的局部坐标处弹出，由系统处理屏幕边缘避让；提供所属 frame，并仅在用户打开本体菜单时激活应用。

本体隐藏与顶部菜单共用同一持久化可见意图操作，退出共用既有清理路径。行为模块不引用 Electron 或菜单对象。纯 TypeScript Timeline 为 XState 延迟、互动时间戳、行走和下落提供同一活动时间；菜单期间冻结时间，关闭后扣除暂停长度。渲染器暂停所有绘制调度，保留最后可见 Canvas，恢复时沿原动作进度继续。冻结期间不消耗完成事件；过期动作身份仍由原契约隔离。

隐藏、系统暂停、显示配置变化及退出显式解除菜单暂停，不依赖 OS 必然回调。晚到的原生回调按菜单身份隔离；同步弹出异常记录日志并恢复。没有新增任意 IPC 频道或运行时测试开关。

## CI Canvas 观测修正 — 2026-10-21

GitHub Actions 运行 `39561737047` 在 `tests/context-menu.test.ts:197` 失败：受控菜单跟踪的 Control-click 关闭后，当前 Canvas 不属于之前采集的待机像素集合。失败截图保存为 `issue-22-ci-menu-failure.png`。此前用户的“都通过”是真实桌面验收，不能据此把该 CI 失败视作成功。

调查先列出并区分五个可证伪解释：Canvas 读回历史改变颜色／alpha 舍入、采样漏掉待机帧、Control-click 误发普通点击、菜单没有解除暂停、自主活动等待到期。原测试在本机 Retina 默认比例通过；只把测试启动比例固定到 CI 的1x，即稳定复现同一断言失败，日志 `issue-22-ci-1x-red.log`。

临时边界诊断观察到宠物持续 resting、同一 actionId、frozenAt 为 undefined、document.hidden 为 false，Canvas 画面仍随待机帧变化；主进程只收到 context 输入，没有普通 press/release。这些读取仅用于排查，未保留为验收断言。初始引用只调用 toDataURL，而 body() 为寻找不透明输入点另外调用 getImageData。将场景缩小为“采集待机引用 → 在待机绘制之间执行三次相同 body() 像素读回 → 比较待机输出”，完全不发送鼠标输入、不打开菜单，也能复现精确像素不匹配。该最小 RED 日志为 `issue-22-ci-minimal-red.log`（11.57秒）。

探针 PNG 的最近同姿态样本有23575个共同可见像素，最大可见 RGBA 差为2／2／2／1，alpha>127轮廓只有2个像素不同。差异还出现在 alpha 为253／254的半透明躯干，不能归结为“仅边缘不同”。已确认是测试中不同 Canvas 读回历史造成精确输出差异；是否由特定 GPU／CPU 后端切换触发，没有直接后端证据，不作确定判断。

修正仅在测试：与既有 app/autonomy 测试一致，每次编码引用及观察图像前走相同 getImageData 读回路径，镜像引用同样处理；默认强制1x，让 Retina 开发机持续覆盖曾失败的 CI 路径，仍允许用 MOSEY_TEST_SCALE_FACTOR 指定比例。继续使用完整图片精确相等，没有像素容差、没有放宽断言，也没有加长超时。最小场景随后通过（10.09秒，`issue-22-ci-minimal-green.log`）；原完整菜单场景在1x通过（30.26秒，`issue-22-ci-1x-green.log`）。临时探针和最小诊断文件已删除，永久回归仍是实际 Electron 输入、Canvas 输出与窗口行为的原完整测试。
