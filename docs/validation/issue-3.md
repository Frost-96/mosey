# #3 清醒点击实现与证据边界

当前范围（2026-10-21）：保留已实现的点击互动，仅取消点击后保持原输入框键盘焦点的验收要求，允许重新点击输入框恢复输入；不采用私有 AppKit 焦点适配。下文 2026-10-20 的焦点缺口与整体暂缓决定为历史记录，以文末最新决定为准。

2026-10-20；本机 macOS 27.0.1、Apple Silicon；Electron 44.9.1 / 内置 Node 24.22.0。

## 实现

XState 在休息状态收到有效身体点击后按 Math.random 的三个等宽区间选择歪头、伸爪或翻肚。反应状态不处理后续点击，不创建队列。可调点击合并间隔为 350ms（上次接受的点击起算），不是已确认产品要求。完成消息携带 actionId，仅当前有效动作可以完成；隐藏取消动作并递增编号，过期帧／点击／完成消息被忽略。输入来自受限 preload，Zod strict schema 验证，主进程校验发送窗口及主 frame。

Canvas 播放时间按实际经过时间选帧；跳过过期帧，不补播。每次绘制发送动作编号与帧编号，主进程仅使用对应版本化图集的 hitRows。alpha 阈值 128，命中数据和显示 PNG 从同批最终 2x 像素生成。点、素材像素、锚点使用同一换算；不使用图片矩形或 CSS pointer-events 代替轮廓。

歪头、伸爪各 9 帧、1470ms：`idle,0,1,2,2,3,1,0,idle`；翻肚 10 帧、1610ms：`idle,0,1,2,3,3,2,1,0,idle`。除中间重复的完整姿态保持 350ms 外，每帧 140ms。上述时长是初始可调值。所有动作从精确待机像素进入并回到同一待机像素；同动作所有姿态共用等比缩放比例，按最低可见像素对齐地面，保留完整轮廓。生成姿态之间仍可能有脸部、比例与构图变化，流畅、有趣及长期观看自然度需要实际尺寸试用评价。

窗口设置 focusable:false、acceptFirstMouse:true，showInactive；隐藏后立即恢复整窗鼠标穿透并清除光标轮询 timer，显示时恢复轮询，关闭时安全清理 timer。主进程每 8ms 查询真实光标并据当前帧 alpha 切换 ignoreMouseEvents，渲染帧报告时也刷新。8ms 是实现参数，没有实时保证。快速进入并立刻点击可能早于轮询；渲染到帧 IPC 生效之间也存在异步窗口。这条 Electron 轮询路线尚不能保证规格要求的真实首次点击可靠性。没有引入未经验证的原生输入能力。

## 暂缓决定 — 2026-10-20

用户真实桌面验收发现：在 Codex 输入框打字后点击宠物，必须重新点击输入框才能继续打字；其他所列检查报告无异常。普通窗口及 `type: panel`、公开 AppKit 样式设置两条路线均未消除焦点症状。临时事件观察捕捉到点击时前台应用切换到 Mosey。早先只有初始状态的采样不足以证明全过程没有切换；观察器返回的鼠标目标进程号属于观察器自身，不能作为系统投递目标证据。

本地实验分支 `ticket/3-focus-panel` 的私有 AppKit `_setPreventsActivation:` 适配得到用户复测“可以继续写，透明处也正常”，同一人工复现脚本从失败转为 `REQUIRES_RECLICK=no`；事件期间前台标识保持 Codex。仅此本机范围通过，不外推其他系统或未来版本。该原生实验还通过了既有开发／打包整应用检查；缺失原生模块场景的额外验证没有形成可靠通过结果，不能宣称兜底已经验收。CUA 随后观察到 macOS 旧窗口恢复提示，选择“不重新打开”后应用正常启动，为此前 ready:false/windows:0 的停滞提供了实际线索。

该方法为私有接口，没有 macOS 升级兼容承诺；拖动、全屏避让及重建窗口尚未验证。[Electron 上游问题](https://github.com/electron/electron/issues/53889) 与 [修复 PR](https://github.com/electron/electron/pull/54807) 提供背景，核对时 PR 仍开放未合入，不能视为稳定版本修复。方法存在检查只能处理一部分失败，不能保证未来语义不变。
