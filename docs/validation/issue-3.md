# #3 清醒点击实现与证据边界

2026-10-20；本机 macOS 27.0.1、Apple Silicon；Electron 44.9.1 / 内置 Node 24.22.0。

## 实现

XState 在休息状态收到有效身体点击后按 Math.random 的三个等宽区间选择歪头、伸爪或翻肚。反应状态不处理后续点击，不创建队列。可调点击合并间隔为 350ms（上次接受的点击起算），不是已确认产品要求。完成消息携带 actionId，仅当前有效动作可以完成；隐藏取消动作并递增编号，过期帧／点击／完成消息被忽略。输入来自受限 preload，Zod strict schema 验证，主进程校验发送窗口及主 frame。

Canvas 播放时间按实际经过时间选帧；跳过过期帧，不补播。每次绘制发送动作编号与帧编号，主进程仅使用对应版本化图集的 hitRows。alpha 阈值 128，命中数据和显示 PNG 从同批最终 2x 像素生成。点、素材像素、锚点使用同一换算；不使用图片矩形或 CSS pointer-events 代替轮廓。

歪头、伸爪各 9 帧、1470ms：`idle,0,1,2,2,3,1,0,idle`；翻肚 10 帧、1610ms：`idle,0,1,2,3,3,2,1,0,idle`。除中间重复的完整姿态保持 350ms 外，每帧 140ms。上述时长是初始可调值。所有动作从精确待机像素进入并回到同一待机像素；同动作所有姿态共用等比缩放比例，按最低可见像素对齐地面，保留完整轮廓。生成姿态之间仍可能有脸部、比例与构图变化，流畅、有趣及长期观看自然度需要实际尺寸试用评价。

窗口设置 focusable:false、acceptFirstMouse:true，showInactive；隐藏后立即恢复整窗鼠标穿透并清除光标轮询 timer，显示时恢复轮询，关闭时安全清理 timer。主进程每 8ms 查询真实光标并据当前帧 alpha 切换 ignoreMouseEvents，渲染帧报告时也刷新。8ms 是实现参数，没有实时保证。快速进入并立刻点击可能早于轮询；渲染到帧 IPC 生效之间也存在异步窗口。这条 Electron 轮询路线尚不能保证规格要求的真实首次点击可靠性。没有引入未经验证的原生输入能力。

## 尚未通过的验收

Playwright window.mouse 是定向应用输入；Canvas 截图、窗口属性和主进程调用不能证明跨应用真实系统路由。没有取得以下证据，因此 #3 保持未完成：

- 前台真实编辑器覆盖宠物窗口下方时，身体内部、边缘及透明洞／角落的点击实际分别到达宠物或编辑器。
- 从窗口外快速移入后的首次真实鼠标点击可靠触发反应。
- 以上输入全过程前台编辑器保持键盘焦点，继续输入仍落在编辑器。
- 真实桌面尺寸下完整三种动作循环及与待机衔接的动态视觉验收。

本轮没有改变已接受的 #2 验收结论，也没有把本票系统路由证据缺口表述为已通过或系统必然失败。

## 代码审查修复与 API 可行性边界

审查修复后 `pnpm check` 通过，真实开发整应用测试 1/1 通过（15.57s）；最终集成打包复核由集成分支执行。

Standards P2 已修复：8ms 光标轮询仅在窗口显示时运行，隐藏立即取消调度并释放输入，关闭清理 timer。整应用测试追加动作中隐藏／恢复后回到待机、再次点击能触发反应的可观察验证；没有以内部计时器字段代替验收。

本机检查已安装 Electron 44.9.1 的 `node_modules/electron/electron.d.ts`：`setIgnoreMouseEvents` 是整窗鼠标忽略开关；`acceptFirstMouse` 只决定非活跃窗口点击是否传给 web contents，不能替代 alpha 系统路由；可表达系统输入区域的 `setShape` 标明只支持 Windows/Linux，不支持本次 macOS 目标。安装包未提供 Chromium/Electron 的完整 C++ 实现源码，不能把类型声明检查说成内核实现验证。当前本地 API 检查没有发现能直接在 macOS 上设置逐帧 alpha 系统输入区域的现成 Electron 能力。

因此 Spec P1 的帧 IPC／光标轮询竞态与真实桌面证据缺口保持开放。原生 NSWindow 命中扩展或全局主动事件拦截属于候选替代路线，前者需验证 Electron/AppKit 集成是否真能把事件交给下层应用，后者可能有辅助功能／输入监控授权及维护成本；本轮均未验证，不能承诺免授权或宣称解决。没有新增原生桥、权限要求或系统钩子。
