# Issue #31 — 设置窗口、大小预设与配置迁移

验证开始于 2026-10-22，最终验证完成于 2026-10-23（Asia/Shanghai）。切片范围是 #31；没有实现 #32 滑块或 #33 开机启动迁移。设置页的开机启动区域指向现有菜单入口。

## 已实现

- 菜单和托盘的“设置…”复用一个可聚焦窗口；宠物窗口始终单独管理。宠物隐藏时可打开设置，关闭设置保留宠物进程与隐藏意图。
- 单页依次显示已选中的柯基、当前数值与小／中／大预设、开机启动说明。没有宠物预览、切换、导入、下载或恢复默认按钮。
- 70／160／240 DIP 预设；160 是默认值。主进程使用数值作为唯一大小值，接受 70–240、10 DIP 步进；数值 110 的加载、无预设选中、绘制、拖动和回到底部也经过整应用验证。
- 配置升级为 version 2；旧 small／medium／large 映射到 70／160／240，旧缺失大小映射到 160。迁移写入使用既有临时文件替换／有效备份保护；写入失败不覆盖已验证的运行中选择。
- 保存失败时保留上次成功保存值并显示错误；重试继续尝试失败目标；新选择清除旧失败目标。主进程同步提交请求，设置渲染进程忽略已被后续选择替代的响应。
- 大小菜单已移除；本体菜单暂停／恢复和实验诊断入口没有改动。开机启动仍从现有菜单管理。
- 设置 IPC 限定设置窗口主 frame，宠物 IPC 限定宠物窗口主 frame；整应用测试验证两种窗口不能调用对方接口。

## Red → green 证据

1. 新设置验收测试首次开发版运行失败：期待默认 160，实际旧默认 240（16.57s）。截图：[初始失败](issue-31-red-default.png)。断言发生在素材加载完成前，截图只记录该时刻，不作为完整绘制证据。
2. 迁移测试失败：重启后主配置仍是 version 1、size small，而期待 version 2、size 70（5.81s）。随后增加原子迁移提交；三个旧档位、缺失档位、隐藏意图和备份恢复均通过。
3. 70 DIP 在 DPR 2 下的旧固定不透明像素门槛失败：实际 7885，小于旧门槛 8000。改为窗口面积的 20%，保留绘制存在性的验收目的，避免固定像素门槛误拒最小尺寸。[失败截图](issue-31-minimum-opacity-failure.png)。
4. 打包版真实设置窗口验证出 CSS 未生效：期待左边距 32px，实际 0px（3.02s）。Vite 把 media 门控的样式内联成 data: URL，被现有 CSP 拒绝；构建改为外部资源，没有放宽 CSP。[打包样式失败](issue-31-red-packaged-css.png)。
5. 最终视觉检查又发现生产 CSS 加载顺序覆盖设置页背景／滚动属性；新增断言失败：实际背景为 transparent，期待 rgb(246, 245, 242)（2.82s）。随后用明确的设置页根标记限定样式，增加失败状态下页底说明可滚动到视口内的断言。[级联失败截图](issue-31-red-packaged-cascade.png)。

## 证据边界与清理

每个测试使用隔离用户目录并在 `finally` 关闭自己启动的 Electron 应用、停止自己的 Forge 进程组、删除临时配置／复制应用；失败路径保存截图。桌面上原有的其他任务应用进程保持不动。
