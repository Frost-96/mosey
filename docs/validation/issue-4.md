# #4 随时抓起柯基，松手后回到底部

2026-10-21，本机 Apple Silicon/macOS 27.0.1，Electron 44.9.1。此记录区分整应用定向输入证据与真实系统输入验收；拖动时保留原工作应用键盘焦点的要求没有豁免。

## 实现

沿用 alpha 命中，仅身体内的按下可建立手势。小于 5 个桌面点的移动在松手时成为点击；超过阈值才开始拖动，释放不会触发点击。原点击反应内单纯点击仍被合并，拖动则可打断反应。回到底部的任意阶段按下身体立即抓住，先停止旧调度，保持当时窗口位置；继续拖动以原始屏幕坐标差计算，不因新姿态跳变。

命中使用最后一次实际绘制的动作/帧；行为状态已转换而下一帧尚未绘制时，旧画面仍可抓取。按下允许对应当前状态或当前显示帧的编号；旧 DONE/帧报告仍严格按当前动作编号检查。该改动缩小转换空档，但没有消除绘制到帧报告之间的异步系统路由窗口。

手势编号与动作编号独立。动作开始（DRAG_START/RELEASE）、取消（CANCEL）及完成（DONE/LANDED）是显式事件；旧动作完成编号和旧运动调度不能完成新动作。preload 继续使用有限 IPC、strict Zod 校验及主 frame/发送者检查。未逐帧传图片，未引入物理/动画库。

渲染侧使用公开 Pointer Capture，在原窗口外继续接收指针移动与释放；捕获期间主进程暂停透明区域穿透。按下后按屏幕坐标移动窗口，所有位置约束在主显示器 workArea；地面是该区域底部。松手播放 360ms 扑腾，再由主进程按 `originY + 180*t + 1800*t*t`（t 秒）每 16ms 计算下落，达到地面切换落地蹲伏，再回待机。5pt/360ms/速度/加速度/采样周期均为可调初值。

松手、pointercancel、lostpointercapture、buttons 丢失、窗口失焦会终止捕获；已拖动的手势回到底部，未达到阈值的取消不产生点击。隐藏、页面重载/离开、渲染进程退出/无响应、锁屏/休眠、显示器布局改变会取消动作和调度并重新对齐地面；关闭/退出清理调度。上述生命周期中未实际驱动的系统事件不能仅凭处理器存在算验收通过。

素材来源、提示、播放顺序和锚点见 [素材记录](issue-4-assets.md)。

## 仍需真实桌面验收

Playwright mouse 向被测试页面定向投递；其窗口外坐标、Canvas 截图、getBounds 和窗口属性不能证明 macOS 跨应用系统路由、系统捕获或键盘焦点。自动化通过不等于本票所有验收通过。

仍保留 `focusable:false`、`acceptFirstMouse:true`、`showInactive` 的公开 Electron 窗口配置；没有私有 AppKit、全局事件拦截或权限要求。#3 已观察到在相同公开窗口路线下真实按下可激活 Mosey；用户仅取消点击后保持焦点要求，未取消 #4 拖动的该要求。此次 Pointer Capture 没有提供阻止初始 macOS 激活的新能力，因此不能声称解决此问题，也不能用参数值证明焦点保留。

必须真实验证：在前台编辑器输入后抓住宠物，跨原窗口拖动和释放，再继续输入是否仍落在原编辑器；透明处路由及快速移入首击；拖动中取消/输入丢失后是否停止跟随；扑腾/下落/落地任意阶段再抓取及屏幕边缘约束。系统锁屏/休眠与显示器变化取消尚无真机证据。公开路线如实际抢焦点，需要明确调整规格或另行验证公开平台适配，不能将 #3 的豁免扩展到本票。
