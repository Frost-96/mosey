# #4 CI：1x Canvas 重载后的精确画面判定

2026-10-21。GitHub Actions `39543694595` 与 `39543835237` 均在开发整应用测试的同一断言失败：活动拖动期间 `location.reload()` 后，实际窗口已回到地面，Canvas 的 PNG 字符串却不属于重载前的精确待机帧集合。失败截图是完整站立姿态，不能据此解释为宠物仍被抓住或下落未完成。

## 复现和诊断

原实现工作树的完整整应用用例仅添加 Electron 启动参数 `--force-device-scale-factor=1`，便在本机 macOS 27.0.1 复现远程 macOS 15 的同处失败（41.82s）。因此操作系统版本不同不是触发的必要条件；原本本机 2x 路径通过，没有覆盖这个 1x 问题。

通过原有 Electron 输入/Canvas/窗口位置边界缩小复现，去掉点击反应、三阶段再抓取、屏幕边界和 Dock 诊断，只保留原用例的初始画面读回与截图、待机帧采集、向上拖动、重载及同一精确画面断言。缩小后的 RED 14.30s；单变量修正后 GREEN 9.97s；撤回该变量后再次 RED 13.78s。更小的场景（不保留原画面读回/截图顺序）不再失败，未把这个不同的通过场景当作复现。

原待机采样已反复调用 `getImageData` 做不透明轮廓验证，新文档重载后却只用 `toDataURL`。探针记录重载前后都是 DPR=1、240×240，重载前有三个独立待机画面，重载后有相应站立姿态。解码比较同一姿态的 PNG：

- 完全不透明区域的 RGB 全部精确相同。
- 半透明边缘约 2500 像素的 alpha 不同，最大差值仅 1；其中一个对应帧有三个像素跨过 alpha=128。
- 因此不是单纯 PNG 编码字符串不同，也不是窗口/Canvas 尺寸变化或漏采某个待机姿态。

让每次 `pixels()` 在编码前都经过相同的公开 `getImageData` 读回，便使原精确断言通过；撤回该单一变化会再次失败。由此确认采样前 Canvas 读回历史是可复现的必要因素。Canvas GPU/CPU backing 的切换及 1x 插值舍入是合理解释，但没有检查 Chromium 内部实现，不能把它描述为已证实的引擎根因。

## 修复与回归

仅修改测试观察方法：每次画面采样都先执行相同的公开 Canvas 读回，再保留原 `toDataURL` 精确比较。没有扩大容差，没有删除姿态/位置断言，没有增加原 5000ms 超时，也没有改应用运行时代码或素材。默认测试应用明确使用 1x，使 Retina 开发机也能覆盖回归；`MOSEY_TEST_SCALE_FACTOR=2 pnpm test:dev` 保留原 2x 路径。普通打包应用启动不附加测试参数。

调试时的缩小测试、前后 PNG 和读回 JSON 保存在 `/tmp/mosey-ci-*`，未提交临时探针。正式回归仍是完整真实 Electron 整应用用例，没有新增内部状态测试或普通浏览器替代。

最终本机完整验证和后续远程运行结论见本记录后续追加及 CI；本修复不补足拖动焦点/跨应用捕获或动态视觉验收证据。

完整开发整应用验证：修正后的 1x 用例通过（42.64s），显式 2x 用例通过（42.84s），各 1 passed / 1 packaged-only skipped。随后显式 1x 打包用例在更早的点击反应中抓取断言处失败（窗口 y 留在地面，line379）；这是不同于重载画面哈希的失败，正在独立诊断，不能把开发通过写成打包/远程全部通过。

## 打包 1x：真实鼠标与定向鼠标混入

第二次打包 1x 运行在相同场景复现失败：按下/移动均已接受，窗口先抬到 y=249，但在按住等待期间回到 y=716。临时输入/IPC/实际窗口位置记录显示：系统鼠标实际停在 (948,513)，Playwright 的定向屏幕坐标却在 (981.67,429.33)；窗口移动到真实鼠标下方后，同一时刻到达 `lostpointercapture` 和 `pointermove buttons=0`，事件屏幕坐标为真实鼠标的 (948.66,513.05)。随后应用发送 cancel、短暂扑腾、下落、落地。没有对应 blur 事件；不是旧动作完成或 press 被丢弃。

因此这次失败是两条输入路径混入造成的真实捕获丢失，应用的取消行为符合要求。没有为使测试通过而忽略 buttons=0、捕获丢失或修改主进程状态。测试现在通过公开 BrowserWindow 位置接口将普通拖动场景布置在远离当前系统鼠标的主屏边缘，非必要的水平移动改为竖直抬起；边界测试及特意调用公开 Pointer Capture 释放造成的取消用例均保留。重载拖动前会再次布置位置，避免边界测试把窗口留在真实鼠标一侧。

该布置只分开测试的真实鼠标与定向输入，不会移动系统鼠标，没有引入 OS 输入合成、私有接口、内部手势注入或屏蔽取消。它也不能充当真实系统跨应用捕获/焦点证据。临时事件记录在 `/tmp/mosey-ci-packaged-*`，正式代码中未保留调试监听器。

一次未加事件探针的边缘布置运行仍在同一抬起位置断言失败（18.90s），当次没有事件链，不能仅凭截图将其归为已证实的同一原因。随后带探针的边缘布置完整打包 1x 用例通过（2 passed，39.50s）：记录的真实鼠标位于 (673,590)，普通抬起期间窗口始终位于另一侧 x=1230，未发生意外捕获丢失。最终移除探针后的结果在下文追加；保留这条中间失败，不将一次通过描述为所有间歇问题已消除。

## 最终无探针本机验证

边缘布置、去掉临时监听器后的完整运行：打包 1x 2 passed（38.86s），开发 1x 1 passed / 1 packaged-only skipped（41.75s），开发 2x 1 passed / 1 packaged-only skipped（42.95s）。

事件记录还发现，落地的末尾可以先呈现待机像素，再结束动作，因而原“打断点击反应”场景有可能实际抓到了落地尾帧。正式场景进一步要求连续 600ms 的三次画面采样都属于待机，再真实点击并确认已经出现非待机反应，随后抓住并保持超过原反应时长。这个澄清继续只使用公开画面/时间/输入，不检查内部动作编号或状态。

上述澄清后的最终完整验证：`pnpm check` 通过；`pnpm test:dev`（默认 1x，1 passed / 1 packaged-only skipped，41.90s）；`pnpm test:packaged`（1x，2 passed，40.25s）。2x 的 42.95s 结果在新增持续待机/反应出现断言之前取得，没有声称之后又跑过 2x。应用 `src/`、素材和打包运行时代码没有变化，未因测试修改重新打包。临时探针已移除，未屏蔽任何原有输入丢失/取消处理。

这些通过结果不抹去前文的中间失败，也不将开发/打包定向输入结果外推为系统捕获、键盘焦点或动态视觉验收通过。远程同一提交的不同 CI 结果及最终分支复核由集成记录汇总。
