# 桌面宠物的语言、动画与行为边界

2026-10-20 的技术栈决策以 TypeScript 为主体，并允许集中封装必要的原生适配。这接受少量跨语言维护成本，让行为与角色表现保持可复用，同时由平台层承担窗口、输入和系统能力；Dock 的原生桥接取舍见 [ADR-0003](0003-dock-native-bridge.md)。

角色采用逐帧图片与 Canvas 2D，程序负责位移，避免为以增加动作种类为主的需求引入骨骼、通用物理或第二套渲染器。素材描述与 Canvas API 解耦，绘制和命中共享素材来源与坐标约定，避免角色外观和可交互区域漂移；公共角色包格式不属于这项选择的承诺。大量独立部件或特效出现时再评估渲染方案。

行为采用 XState 表达显式状态与打断关系，接受依赖与学习成本，避免自行扩建状态机框架。主进程拥有行为、位置、运动和系统适配，行为模块保持纯 TypeScript；角色姿态与系统可见性分开建模。渲染进程只承担表现，依据经过时间播放并按需绘制，进程间不逐帧传图片。

进程边界采用 Electron 原生 IPC、共享 TypeScript 契约和 Zod，避免额外的 RPC 框架。沙盒 preload 通过 contextBridge 暴露具体能力，保留 contextIsolation；配置、素材描述和跨进程消息在进入边界时校验，普通内部函数依赖 TypeScript 类型。

工程保持单 package，开发与打包统一交给 Electron Forge 及官方 Vite 插件。选型时已接受插件的实验性与升级兼容成本；依赖精确锁定，工具链升级独立于功能改动，并联合验证开发和打包入口。源码统一使用 import/export，主进程与 renderer 使用 ESM，沙盒 preload 使用兼容的 CommonJS 单文件；类型检查独立运行。精确版本和构建选项以配置及锁文件为准。

持久化采用主进程管理的版本化 JSON，以简单的本地偏好存储代替数据库。主进程拥有用户偏好，开机启动以系统实际状态为准，设置界面不维护第二份权威配置。偏好与动作、拖动、下落等瞬态分离，重启和故障恢复从稳定状态开始。应用采用单实例与有限渲染恢复，接受主进程故障后退出的边界，避免引入常驻守护程序。

测试采用 Vitest 运行器与 Playwright Electron 驱动，围绕整应用对外可观察的行为验收，避免为内部实现建立镜像测试。该组合接受应用生命周期、进程清理和实验性驱动的维护成本；自动化结果与真实跨应用输入、焦点、Dock、登录及工作区证据分别记录，CI 不替代真机验收。

最初仅有宠物窗口与菜单栏时，选择不引入 React/Vue，并允许未来设置界面独立选型。2026-10-26，决定设置页采用 React、宠物保留 Canvas：设置交互逐渐增加，声明式控件与组件生命周期用于管理展示和订阅，代价是引入设置页运行时依赖与新旧区域并存期间的所有权边界。React 仅沿设置页依赖链加载，主进程继续拥有持久化和系统操作，页面展示与通信、请求状态协调分开组织。迁移按独立 DOM 区域推进，React 根内的节点与事件由 React 管理，其余区域继续由原实现管理，避免两个渲染方式争用同一节点；不为此引入路由、组件库或全局状态库。分区迁移范围与验收由 [#43](https://github.com/Frost-96/mosey/issues/43) 和 [#44](https://github.com/Frost-96/mosey/issues/44) 跟踪。
