# 用独立 Swift 进程提供 Dock 可见几何

Dock 攀爬需要真实可见轮廓；普通工作区和窗口枚举得到的整屏矩形不足以作为支撑边缘。项目选择独立 Swift 可执行程序，在本地用 ScreenCaptureKit 分析 Dock 像素，仅通过受限、逐行 JSON 向 Electron 主进程发送几何与状态；像素留在辅助进程内。这承接了平台探针后的选型，并于 2026-10-25 的交付记录中确认落地。

相较 Node 原生扩展，该方式避免与 Node/Electron 扩展 ABI 绑定，代价是维护 Swift 构建、子进程生命周期、协议校验及签名和权限归属。产品捕获与诊断程序保留独立身份并互斥运行，避免诊断覆盖产品身份或同时占用捕获资源。

捕获权限属于实际应用启动链，开发宿主授权不能代替独立打包应用授权；重签后的权限与桌面行为需重新验证。捕获失败时清除 Dock 支撑，保持普通地面活动，不将固定边界包装成真实捕获成功。

应用声明的最低系统版本须与随包原生程序的编译目标一致，避免允许缺少可运行原生能力的系统启动。构建下限由配置表达，经验证的系统范围与捕获成本由 [#11](https://github.com/Frost-96/mosey/issues/11) 的实际证据确认，二者不等同。
