# 自定义角色采用必需基础动作与可选扩展动作

2026-10-28 确认以下待实施的决定：面向用户开放角色素材接入规范，角色素材包必须提供基础动作，可以选择提供扩展动作。这调整了 [ADR-0004](0004-shared-behavior-and-character-assets.md) 中仅面向内部素材、要求完整当期通用动作的边界，继续沿用共享行为与角色表现分离的架构。

主要使用场景是用户不喜欢默认角色时，参照仓库规范与默认角色示例，为自己制作并导入角色。制作与使用由同一用户完成，流程设计以个人自用为依据，不预设另一位素材作者替用户制作或分发角色。

要求每个素材包提供所有新增动作，会持续提高制作门槛，并使新增动作影响已有自定义角色。按基础动作与扩展动作区分，允许不同角色具备不同的扩展动作能力，代价是应用需要识别和呈现动作可用性；缺少扩展动作时，该动作明确不可用，不以静态图片冒充已支持。

自定义角色只改变外观和应用已定义动作的表现，行为规则与动作类别由应用管理。素材作者提供透明动作帧图或精灵图及少量描述信息，应用负责校验和预览。首版不接受素材包定义的新行为或附带脚本，也不承担从单张角色图生成完整动作的工作；这保留了共享行为的边界，代价是作者不能通过素材包扩展玩法。

首版基础动作确定为待机、行走、拖拽、下落和着陆，使每个导入角色都能参与落地与固定放置两种位置模式。睡眠、伸懒腰、招手、跳舞等作为扩展能力，缺少素材的行为不触发，对应动作菜单项显示不可用。固定放置模式不免除基础动作要求，避免切换位置模式时才发现角色无法使用。

首版提供规范、示例模板和 ZIP 素材包导入。2026-11-06 确认采用方案 B：用户将透明 PNG 源图片与声明式描述配置整理成 ZIP，由已安装应用完成检查、图片加工、点击轮廓等派生数据生成和预览，经用户确认后才正式安装并加入角色列表。用户在已有工具中制作图片、填写描述并准备 ZIP，无须下载项目源码、安装开发环境、运行预处理命令或提供预编译图集。应用不提供完整动画编辑器，也不自动创作动作。该选择降低个人自制角色的接入门槛，代价是应用需要随安装包提供加工能力，并承担加工失败反馈、临时资源清理与缓存管理。

公开规范以默认角色的实际素材接入流程为范本，在仓库中提供规范文件和可仿照的示例。通过提炼已有流程形成公共接口，而非另起一套与内置角色脱节的制作方式；当前内部格式中的硬编码与生成数据仍需审视，不能原样视为公共契约。默认角色采用逐帧裁切、落脚点和时长描述，其原图布局与加工后的统一坐标不直接成为所有作者源图片的限制。

2026-11-06 进一步确认：接口完成后，新增、更新或删除用户角色只操作角色素材包及应用自动维护的安装与选择记录，无须修改应用源码、代码中的角色名单、角色专属加载分支或构建脚本，也无须重新编译应用。图片与描述信息共同构成素材包，角色身份、名称和已定义动作的表现由包提供，应用通过通用契约识别、校验与加载。这个选择将角色增删与代码发布解耦，代价是通用接口需要承担能力发现、资源生命周期与兼容校验；新增应用尚未定义的行为仍不属于单纯添加角色素材的能力。首次实现该接口所需的应用改造，与此后的角色增删操作分开处理。

用户角色及派生缓存保存在应用管理的用户数据区域，不修改已安装应用的程序包，也不依赖构建时收录。角色目录通过通用契约读取身份、名称与动作能力；安装、更新和删除同步管理素材、派生缓存与自动维护的记录。这使同一已安装版本能够接入源码中从未登记的新角色，同时要求应用处理资源失效与同标识更新。

角色包采用稳定角色标识区分身份，重复导入同一角色时由用户确认更新，更新失败保留旧版。此选择支持作者持续改进同一角色，而不因每次导入产生重复条目；代价是包作者需要保持身份标识稳定。取消预览不安装角色，加工或校验失败不破坏已有角色。允许删除自定义角色，删除当前角色前须成功切回鲸鱼娘，内置角色不提供删除入口。

上述决定待实施，不表示公共格式已经实现。精确图片布局、配置字段与版本兼容仍待确定。

实施规格与验收记录由 [#70](https://github.com/Frost-96/mosey/issues/70) 跟踪。
